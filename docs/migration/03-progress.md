## 2. 옮긴 것 (Apps Script, 구글 시트 → Worker, D1)

- **로그인**: 아이디(연락처) + 비밀번호. 첫 로그인은 생년월일 → 비밀번호 바꾸기 강제(`mustChange`). PBKDF2 해시, 실패 잠금, 30일 세션(하루 한 번 자동 연장 `renew`), 서버 로그아웃.
- **비밀번호 초기화**: 운영진이 회원 비밀번호를 공용 초기화 비밀번호로 되돌림(값은 secret). 운영진은 관리자 비밀번호는 못 바꿈.
- **회원가입 신청 → 운영진 승인**, 프로필 사진(R2), 갤러리, 채팅 랭킹, SHRED LOG, 스노우라이브 연동, 소모임 정모, 시즌방 — 응답 모양은 Apps Script 때와 같게 유지해 화면 수정 최소화.
- **데이터 옮기기**: 운영진이 받은 엑셀 → `backend/scripts/import.py`로 SQL 생성(생성물, 엑셀은 gitignore) → D1에 넣음. 지역은 `normalize-regions.ts`로 정리.

## 4. 운영진 페이지 (`/admin`)

탭 순서: 가입 신청 | 회원 | 시즌방 정산 | 시즌방 주주 | 채팅 랭킹 | 사진 보관 | 로그인 이력 | 조 편성 | 운영 기록(관리자만).

- 위쪽 요약 칩: 활동 회원 N / 전체, 가입 대기 N(있으면 주황). 누르면 해당 탭.
- **가입 신청**: No, 승인/거절.
- **회원**: No, 검색, 상태 배지 + [수정] [비번 초기화] [상태 변경](활동/정지/탈퇴). 권한 변경은 관리자만. **엑셀 다운로드**(지금은 CSV 임시 양식 — 양식은 나중에 정하기로 함, 다운로드는 운영 기록에 남음).
- **시즌방 정산**: 시즌, 달 선택, 날짜별 한 줄(No, 날짜, 이름, 구분, 금액) + 합계. 주주는 0원.
- **시즌방 주주**: 시안 D — 이번, 지난, 지지난 시즌 카드, ✕ 빼기, '+ 주주 더하기', '지난 시즌 주주 그대로 가져오기', 바꾸면 바로 저장.
- **채팅 랭킹**: 오픈채팅 내보내기 CSV 올리기.
- **사진 보관**: 갤러리 시즌 보관 상태, 수동 보관.
- **로그인 이력**, **운영 기록**(누가 무엇을 바꿨는지).
- **조 편성**(정모, 체육대회용, `free-snow-summer`의 팀 설정 참고): ① 참가자 — 활동 회원 고르기 + 게스트 ② 자동 편성 — 팀 수, 성별, 운영진 고르게(인원, 성별, 운영진 모두 조마다 차이 1 이하), 조 이름 고치기, 사람 옮기기. 저장은 선택(행사별). 점수판은 요청으로 뺌.

## 6. DB 규칙

- 모든 테이블: `is_active`(소프트 삭제 — 지우지 않고 0) + `created_at`, `updated_at`(트리거가 자동으로 찍음, **항상 맨 뒤 열**). 예외: `members`는 `status`(active/suspended/withdrawn)로 관리.
- `members` 열 순서: `id, status, phone, name, gender, birth, region, area, private_contact, role, sort_no, joined_at, approved_at, created_at, updated_at`.

## 7. 보안에서 지킨 것

- 회원에게 다른 회원의 생년월일, 성별, 비공개 연락처를 절대 보내지 않음. 다른 회원은 이름만.
- 비밀값은 전부 Cloudflare secret / 로컬 `.dev.vars`(gitignore). 저장소엔 이름만.
- 허용 출처(CORS)는 사이트 주소만.
- 갤러리, 프로필 사진은 공개(사용자 결정 — 메인, 소모임에서도 공개). **회원 전용 게시판 글의 사진은 서명된 주소**(기한 있음)로만 열림.
- 게시판 스팸 제한: 글 시간당 10개, 같은 제목 10분, 댓글 시간당 30개, 같은 댓글 5분. 가입 신청은 운영진 승인이 있으니 추가 장치 없음(사용자 결정).
- 회원 명부 다운로드, 권한/상태 변경, 삭제는 운영 기록에 남음.
- 엑셀, SQL 생성물 등 실제 회원 데이터 파일은 gitignore.

## 8. 배포 방법

1. `cd backend && npm test` — 하나라도 실패하면 멈춤
2. `npx wrangler d1 migrations apply DB --remote` (새 마이그레이션이 있을 때)
3. `npx wrangler deploy` (반영까지 10초쯤 걸릴 수 있음)
4. 사이트: `main`에 push → GitHub Actions가 Pages 배포
